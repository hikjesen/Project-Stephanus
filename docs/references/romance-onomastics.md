# D. 欧洲姓名与罗曼语族检索

在用户优先希望自然的欧洲姓名、间接词源联系或某个地区／时代风格时读取。入口可以是拉丁词根，也可以是相关概念或已经找到的姓名；跨语言关系按资料实际提供的类型解释。

## 参考来源与适用范围

- 本地 Onomaverse：已有姓名、本地化形式、转写与其他姓名关系。用 `search_names` 找到具体条目，再用 `find_related_names` 沿记录中的关系查找。
- 本地 Medieval European Name Reference Tool 资料：规范名、词源及保留的历史记录；需要时读取 `get_entry` 中的 `senses`、`etymology`、`attestations`。
- [DMNES Guide](https://dmnes.org/guide)，本地 `data/references/dmnes-guide.html`：解释规范名、实录写法、年代、地区、文献语言和格。规范名不一定在文献中实际出现；历史拼写以具体记录为依据。
- 需要补充某个词源或用法时，按姓名查 DMNES 条目、原词典、历史记录或相关语言的专业姓名资料。仅查当前候选所需内容，不预先扩建跨语言词源库。

## 怎样使用

从 C 获得概念或拉丁词汇后，先提出少量可能的人名／姓氏线索。可查词本身、已知相关姓名或其变体；仅有词根相似时，将其作为检索线索，读到词源或记录后再说明联系。

Onomaverse 的姓名条目没有统一的释义正文；`search_names(query=某个含义, mode="meaning")` 不能覆盖全部姓名。从概念找不到人名时，可利用 Agent 已有姓名知识提出线索，再查姓名写法、关系与参考资料。

对选中的姓名按需读取详情和关系，并根据目标语言、时代及名／姓用途继续选择。关系返回“相似”“文化对应”或“转写”时，不直接改称同源；同样的意象也不意味着词源相同。

希望意大利语、法语、西班牙语等风格时，可按相应语言代码查询已找到的姓名线索，或沿关系查本地化形式。无需逐个语言都查一遍。拉丁词源可以进入现代语言姓名，希腊语来源也可进入欧洲命名传统；输出时标明实际语言与联系类型。

## 选择提示

旧早苗案例中的 Chloe／Gratia 提供两种可继续探索的入口：原义放宽后的意象联系、同音借义后的姓名选择。Issue 提到的 Flora、Fiore、Novella 等仅作检索方向；本指引不预先认定其词源、性别、名／姓用途或彼此关系。

姓与名分别选材，再判断组合是否适合所选语言和风格。数据库中出现一条历史记录，可以支持“曾有此形式”；某年代的实录本身不等于当代常见。

最小形成链为「概念或词汇 → 姓名线索 → 词源／关系／历史记录 → 所选语言形式」。实际完整姓名若由 Agent 组合，说明组合为本次选择即可。
