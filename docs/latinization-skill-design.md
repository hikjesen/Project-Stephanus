> 初版于 v1.0.0 定稿，现行入口为 [stephanus-latinization v1.0.1](../.agents/skills/stephanus-latinization/SKILL.md)。正式调用以该 skill 为准；下文保留设计阶段的决策与状态，不再并行维护流程规则。“当前不安装”等表述属于当时记录。

修订日期：2026-11-11。状态：按 [Issue #1](https://github.com/hikjesen/Project-Stephanus/issues/1)、若叶睦与古明地恋实践的反馈，补入意象选择、目标语言适配、至少四个完整候选、偏好生僻名形与可选后续修饰。用于后续编写 skill，当前不安装 skill。

## 职责与调用边界

建议名称为 `stephanus-latinization`。用于为创作者将日语姓名转成拉丁语名形或符合所选罗曼语族语言习惯的别名；历史欧洲转写可提供中间材料。数据库提供材料，skill 提供方法与参考，用户选择关联倾向，Agent 继续推导和组合候选。直接复用七个只读 MCP 工具，不调用模型 API，不建立独立 Agent 调度器。

用户给定的读音、目标语言或地区、时代风格优先。关联意象未明确时，先给几种可能性并征求用户选择；随后至少给出四个由姓与名组成的完整候选，采用不同构造路径或风格。其中至少一个明确回应用户选定的倾向，至少一个以历史拼写特点类推及后续适配为主线；其他候选可探索原名的不同联系。用户明确另定数量时按其要求。

本项目选材偏好为“宁可生僻，也不要过于常见”。在目标文化中可解释的稀见名形、历史异写及有参照的创作均可采用，允许明显改变声音、拼写和意义；自然度不以名字常见为前提。基础候选选好后，还可选择性地进行后续修饰。

“拉丁化”在这里涵盖数种创作目标。拉丁语与意大利语、法语、西班牙语等罗曼语族语言分别选定；共同使用拉丁字母不等于具有相同的姓名习惯。其他欧洲语言可按用户要求扩展。历史日语转写默认作为过程材料，用户明确只要历史写法时才以其为成品。强保音、逐义翻译或自由造名按用户偏好调整。

## 暂定选择原则

- 先确认姓名的写法、读音和姓／名。完整姓名未命中时拆分查询；人物读音结合用户或官方资料选择，未确定时简短说明采用的读音假设。
- 让用户选择更想保留的声音、含义或人物意象，以及可接受的变化；这一选择保证至少一条回应方向，不限制整组候选。用自然语言说明选项，不要求用户先选方法编号，也不设置量化权重。
- 默认优先探索较生僻的姓名、历史变体及有参照的方法。查到普通词或常见规范名后，继续考虑稀见变体与可用作姓名的整体形式；初步检索不理想时，可换概念或方法，无需穷尽资料。修饰前的基础名已经应符合此选材偏好。
- 默认不将日语姓名逐字翻译后强拼成拉丁短语。可以保留主要意象、使用间接联系或舍弃部分字义；词义与语法可解释，不等于已经获得自然姓名。
- 姓与名独立推演，再按目标命名风格组合。允许一部分保音、另一部分取意，也允许保留或弱化原姓。单名可作补充，不代替四个完整姓名；避免整组仅替换名字而复用同一创作姓氏。
- 自由创作保留为扩展方法：用户偏好或命名效果适合时可直接采用；默认先探索上述材料。创作部分简短注明，不要求每个候选都有历史实录。

## 先选关联倾向，再生成姓名

先做足够的输入解析和轻量查询，以便展示有材料支撑的可能性；随后通常提出二至四种意象／音形倾向，每项简述「原名材料 → 可联想的方向」及主要取舍。让用户选择、混合、否定或补充，避免用一组已经生成的名字代替意象讨论。

例如「若叶睦」可先展示：

| 可选倾向 | 与原名的联系及取舍 |
|---|---|
| 萌发、新生与成长 | 从若葉的嫩叶、新生意象展开，可弱化具体植物与“绿色” |
| 青绿、植物与生命力 | 保留若葉的视觉意象，可放宽为植物或生机，亲和含义暂不突出 |
| 亲近、联结与和睦 | 从睦展开，若进一步放宽为“和平”等概念，先说明这一步转移 |
| 隐约的声音轮廓 | 选取部分音节或节奏，允许明显改形，最终仍采用目标语言的姓名模式 |

简短询问“哪种倾向更符合你的意图？可以混合或另提方向”。目标语言也未明确时，在同一轮合并询问，例如拉丁语名形、意大利语、法语或西班牙语；已明确的偏好沿用，不重复询问。

在需要用户选择时，等其回复后再进行依赖该选择的扩展检索、命名加工和完整候选生成。用户已明确意象与语言，或明确委托 Agent 自选时，可以直接继续；一项满意结果只作为本次偏好线索，不自动转成后续所有姓名的固定意象。没有回复不视为选中了默认项。

用户选定的意象用于保证至少一条候选方向。历史拼写路线主要依据原读音与历史材料，无需强行解释成同一意象；其他路线也可采用原名的别义、同音借义、人物材料或另一种风格。用户明确规定的语言、地区等要求仍共同适用；没有严格限定时，可并列不同的拉丁语／罗曼语族风格并标明。

## 组织完整候选与可选修饰

至少四个完整姓名中，安排一条明确回应用户所选倾向的路线、一条独立的 A 历史拼写路线，其余通过不同构造或风格扩展。两类路线可以互用材料，但只在语义候选的姓氏上替换一个历史拼写，尚不能代替独立的历史路线。无需让四类方法各占一个名额，也无需为其他每条意象重新征求选择。

先筛选较生僻的基础姓名，再决定是否修饰。常见规范名可以作为词源和查询入口；例如 Amanda 可引向 Amandine，但本项目不默认以 Amanda 作为成品，然后靠修饰弥补选材。

可选后续修饰见[共享适配指引](references/target-language-name-adaptation.md)：允许进一步调整音节、词尾、节奏或复合构形，修饰结果可以未被数据库收录。有修饰时同时给出**完整基础姓名 → 完整修饰姓名**，说明参照和改动；两种形式仍只计为一个候选。历史转写后的目标语言适配是该路线的必经加工，与此可选步骤分别记录。

## 先摘要，后详情

- `stephanus_list_sources()`：只在需要了解覆盖和后端状态时调用；完整资源清单通过 `include_resources=true` 取得。
- `stephanus_search_names(query,language,category,source,mode,limit,offset)`：搜索写法、读音或释义。`extra.match` 表示实际匹配方式。
- `stephanus_lookup_words(...)`：日语和拉丁语词目查询；`source="verba",language="la",mode="meaning"` 优先匹配 Smith & Hall 英语词目。
- `stephanus_get_entry(identifier)`：取得保留的义项、词源、词形、相关词、历史资料和来源。原词典文章、用例全文和原始 JSON 已移除。
- `stephanus_find_related_names(identifier,relation,limit,offset)`：查现有变体、相似、文化对应和转写关系，沿用原关系类型。
- `stephanus_transliterate_name(text,scheme)`：复用 romkan，输入是假名或其支持的罗马字；汉字先查读音。
- `stephanus_analyze_latin(text,limit)`：调用 Whitaker/verba 分析已有词形；不是完整的名称生成或变格接口。

罗马字工具目前支持 Hepburn、训令式及假名转换；历史语音转写需另读方法 A 的参考。词形分析仅提供词目和语法线索，姓名使用情况及历史规则另由条目或文献支持。

列表的 `description` 最多 240 字。详情的 `extra.knowledge` 提供：

| 字段 | 内容 |
|---|---|
| senses | 义项、必要标签和适用写法/读音；Smith & Hall 可含 latin_equivalents |
| etymology | 词源说明，缺失时为空 |
| forms | 词形与语法标签，不含重复的整份词条 |
| related_words | 派生、近义、跨语言词汇联系 |
| attestations | 已保留的姓名年代、地区和文献定位 |
| lemma_links | 纯词形或异体对应的词目文字、语言、标签及已找到的条目 ID |

来源由 `extra.provenance` 提供。别名所指词目不明确时，返回原目标文字，不据此假定唯一词源。

## 四类核心方法与按需参考

这些是可选择、可组合的方法，不要求每类各生成一个结果；完整候选组须含至少一条 A 路线。确认用户偏好和候选分工后，只加载实际使用的方法参考。

| 方法 | 适用意图与输入 | Agent 的主要动作 | 按需读取 |
|---|---|---|---|
| A. 历史语音转写 | 从日语声音提取历史拼写材料，再进入目标姓名习惯 | 先据文献转写，再按所选语言的读音、构形与实际姓名参照继续适配 | [历史日语转写](references/historical-japanese-transliteration.md) |
| B. 传统形态拉丁化 | 保留音形，同时获得可解释的拉丁语名形 | 先查已有拉丁形式，再参照外来人名拉丁化的词干、词尾惯例；必要时分析词形 | [人名形态拉丁化](references/personal-name-latinization.md) |
| C. 人文主义语义拉丁化 | 允许明显改名，保留整体含义或主要意象 | 参考语义改名实例，寻找适合作为姓名的整体形式；允许局部保义与间接意象 | [人文主义语义拉丁化](references/semantic-humanist-latinization.md) |
| D. 拉丁词源与概念 → 既有欧洲姓名 | 优先自然的欧洲姓名、历史变体或罗曼语族形式 | 从词汇提出姓名线索，查询已有姓名及其词源、语言和历史记录，再选取变体 | [欧洲姓名与罗曼语族检索](references/romance-onomastics.md) |

A 提供中间音形，目标为拉丁语时可接 B，目标为罗曼语族姓名时可接 D 或有参照的创作；C 可为 D 提供语义入口。涉及新造名形、历史拼写后加工时，按需读取共享的 [目标语言姓名适配](references/target-language-name-adaptation.md)。四类方法保留，共享适配步骤不另建第五套方法。

### 同音借义与自由创作

同音异字是辅助入口：按假名找其他写法，选取新意象，再连接 C、D 或自由创作。例如「さなえ → 佐名恵 → 恵 → grace → Gratia」借用了新选字的含义；不将其覆盖为「早苗」的原义。

自由创作可基于某条候选采用的声音、词根或人物意象；参照具体目标语言中同用途的姓名，处理读音、重音、构形及姓名组合，也可用于基础名之后的可选修饰。允许有较大音形变化，简短保留关联线索。避免把普通词加上 `-a`、`-us` 就默认判为自然人名，也不要求新造词必须已有收录。

## 从材料到候选

查询过程由实际结果决定：姓名解析与少量材料 → 展示关联倾向并取得用户选择 → 分配至少四条完整候选的构造方向 → 寻找姓名／历史规则 → 按各自目标风格适配并组合 → 筛选较生僻的基础姓名 → 按需后续修饰。整体词义优先于拆字；英语可作为查询英拉词库的桥梁，无需成为所有方法的必经语言。

历史拼写方向采用「原读音 → 历史类推中间形 → 目标语言姓名参照 → 最终名形」。比如 Muçumi Wacaba 仅记录第二步；随后应在已选语言中寻找合适的音近姓名，或参照真实姓名模式继续加工。改字母、拼写能读通，尚不足以完成这一方向。用户只要历史转写时沿用其明确目标。

由拉丁词汇转向姓名时，可先尝试词本身、已知姓名形式或词源线索，再对选中的姓名使用 `get_entry`、`find_related_names`。Onomaverse 主要提供写法与关系，不能假定它能按词义查到全部人名；Medieval 的词源、年代、地区资料及按需外部参考可补充。关系类型为相似、文化对应或转写时，按原类型解释。

每个候选简洁给出：**完整基础姓名（名／姓结构）｜可选修饰后的完整姓名｜目标语言或风格、方法｜本条保留的联系及关键依据**。明确指出哪条回应用户选定的倾向、哪条承担历史拼写路线；将历史中间形、完成适配的基础名与可选修饰区分。实际使用的少量 entry ID、文献页码或链接即可，无需逐项评分或长篇免责声明。

## 四类调用示例

**汉字姓名「早苗」：** 确认读音与整体词义后，让用户选择新芽、同音借义、声音轮廓等倾向及目标语言，再进入相关方法。姓氏另作选择，不默认复用直译短语。既有调用及其问题见 [案例与设计复盘](examples/kochiya-sanae.md#设计复盘2026-11-11)。

**假名输入「しんじ」：** 查读音对应的姓名写法；先询问保音还是采用某种字义／人物意象。历史类推读 A，目标为拉丁语名形读 B，再以所选目标语言的姓名参照完成适配。

**已有欧洲姓名「John」：** 以 D 查询 Onomaverse 或 Medieval 的变体、词源和记录，根据语言与风格选取。`und` 表示未确定语言；规范名和文献中的实录写法分别读取。

**无直接对应的自造名字：** 以声音、局部意象或命名惯例寻找入口；材料仍不适合时自由创作，不让空检索阻断任务，也不强求完整保义。

## 后续 skill 的组织

后续 `SKILL.md` 的触发范围为日语姓名的历史转写、拉丁化及欧洲姓名别名创作。入口保留目标、意象选择对话、至少四个完整候选的分工、偏好生僻的基础选材、可选后续修饰、工具要点和按需参考；不复制词库，不创建额外调度器或翻译服务。

本次参考复用本地历史资料与数据库，补充少量可定位的外部来源。历史规则暂以文字指引表达；机器可读规则表仅在后续实际使用需要时增加。保持 compact-v1 数据库与七个 MCP 工具。已有数据库验收及早苗调用记录沿用历史结果，不重跑、不改写为新方法已经通过。

实际调用及后续修订见[若叶睦案例](examples/wakaba-mutsumi.md)与[古明地恋案例](examples/komeiji-koishi.md)。它们保留当时结果和反馈，不将创作结果视为通用语言学准确性验收。
